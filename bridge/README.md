# Lava_test 桥接服务

浏览器与现场设备之间的唯一通道。

## 为什么需要它

页面跑在浏览器里，而浏览器**做不到**这三件事：

| 做不到 | 原因 |
|---|---|
| 连 FTP | 浏览器没有 FTP 客户端 |
| 遍历本机任意目录 | File System Access API 要用户逐个授权，且拿不到绝对路径 |
| SSH 到机台 | 浏览器不存在这个能力 |

所以现场数据必须由本机的一个小服务代劳。

它还顺手解决了另一个问题：**托管页面到 `http://127.0.0.1:8770/`**。
Chrome/Edge 在 `file://` 协议下会禁用 IndexedDB，看板只能退回容量受限的降级存储；
而 `127.0.0.1` 是安全上下文，存储、目录授权等功能全部可用。

## 快速开始

```bash
# 1. 确认有 Python
python --version        # 需要 3.8+

# 2. 自检（验证只读守卫、路径防护、静态托管）
python lava_bridge.py --selftest

# 3. 启动
python lava_bridge.py
#   或双击「启动桥接服务.bat」
```

启动后看到这行就成功了：

```
监听地址 : http://127.0.0.1:8770
看板页面 : http://127.0.0.1:8770/
```

**然后改用浏览器打开 `http://127.0.0.1:8770/`**，而不是双击 HTML 文件。

## 零第三方依赖

只用 Python 标准库（`http.server` / `ftplib` / `urllib`）。

现场机器常常装不了 pip 包，零依赖意味着**有 Python 就能跑**。

唯一的例外是 SSH 的**密码认证** —— 需要 `paramiko`：

```bash
pip install paramiko
```

不装也能用 SSH，但只能用**密钥认证**（走系统自带的 `ssh` 命令）。
启动时会明确报告当前是哪种模式，页面上也会显示「SSH 仅密钥」的提示。

## 只读保证

这不是保守，是产线红线：桥接跑在有测试程序在跑的机器旁边，任何误写都可能影响正在测的盘。

| 防线 | 做法 |
|---|---|
| **端点白名单** | 只有注册过的路由可访问，其余 404 |
| **SSH 命令白名单** | 只放行 `ls` / `cat` / `head` / `find` / `df` / `ps` 等读命令 |
| **写操作特征拦截** | `>` `>>` `\| tee` `rm` `mv` `dd` `chmod` `sudo` `sed -i` … 一律拒绝 |
| **路径白名单** | 文件操作只能落在配置的根目录内，`../` 穿越被拦截 |
| **默认仅本机** | 默认监听 `127.0.0.1`；要远程必须显式 `--allow-remote` + token |

自检会实际验证这些规则：

```
[只读守卫]
  ✓ ls -la /tmp                      放行
  ✓ cat /var/log/x.log               放行
  ✓ rm -rf /tmp/x                    拒绝
  ✓ echo hi > /etc/passwd            拒绝
  ✓ dd if=/dev/zero of=/dev/sda      拒绝
```

## 接口清单

### 服务与配置

| 端点 | 方法 | 说明 |
|---|---|---|
| `/` | GET | 托管看板页面 |
| `/api/health` | GET | 存活 + 各通道状态（结果缓存 30 秒） |
| `/api/net/selfcheck` | GET | 逐个通道的可达性检查 |
| `/api/config` | POST | 页面下发 FTP / SSH / MES 配置 |

> **`/api/health` 不做阻塞网络 I/O。** 通道探测用短超时（3 秒）+ 结果缓存，
> 否则 FTP 不可达时会把整个请求拖满超时，页面上的检测与自动刷新全被卡死。

### FTP 通道

| 端点 | 说明 |
|---|---|
| `/api/scan` | 递归扫描，参数 `root` / `depth` / `limit` / `pattern` |
| `/api/file` | 下载文件，文件名与 mtime 放在 `X-File-Name` / `X-File-Mtime` 响应头 |

### 本地目录通道

| 端点 | 说明 |
|---|---|
| `/api/local` | 列出目录（`path` 为空则列出所有允许的根） |
| `/api/localscan` | 递归扫描 |
| `/api/localfile` | 读取文件 |

### SSH 通道

| 端点 | 说明 |
|---|---|
| `POST /api/ssh/hosts` | 下发机台清单（IP + 工站 + 设备编号） |
| `GET /api/ssh/probe` | 立即巡检一轮（并发） |
| `GET /api/ssh/status` | 取后台巡检快照 |
| `GET /api/ssh/ls` | 列目录 |
| `GET /api/ssh/cat` | 读文件（`max` 限长） |
| `GET /api/ssh/slt` | 取日志根目录下最新的日志文件 |

### MES 通道（协议待定）

| 端点 | 说明 |
|---|---|
| `/api/mes?endpoint=<名字>` | 按配置转发，响应原样返回 |
| `/api/workorder-options` | 工单选项的快捷入口 |

MES 做成**可配置转发**而不是写死协议：现场接口还没定，
所以只按配置拼 URL、注入认证头、把响应原样带回，字段映射交给前端。

## 配置

两种方式，效果相同：

**① 页面下发**（推荐）：在「实时拉取 → 接入设置」里填，桥接收到后立即生效。

**② 配置文件**（适合固化现场信息）：

```bash
python lava_bridge.py --config config.json
```

参考 `config.example.json`。

> ⚠️ 配置文件含密码，**不要提交到版本库、不要外发**。
> 页面侧的「导出完整 JSON」不包含这里的密码 —— 密码只存在桥接侧。

## SSH 巡检在做什么

每 `intervalSec`（默认 60 秒）并发巡检一轮，问三个问题：

```
1. 在线吗？  —— SSH 连得上 = 开机在线
2. 在测吗？  —— 用 ps 匹配测试进程特征（可配置）
3. 测完了吗？—— 日志目录里最新文件的时间
```

**并发是必需的**：产线有数百台设备，串行 SSH 一轮要几十分钟。默认 20 并发。

### 两个容易踩的地方

**① 测试进程特征要按现场配。** 默认值是 `slt|test|ssd|dml|burn`，
现场测试程序名不同的话要在配置里改 `testProcessPattern`，否则「在测」会一直判为否。

**② 巡检失败时沿用上轮结果，但会标明是旧数据。**
SSH 不通时不把旧数据当实时状态展示 —— `stale` 标记会一路传到界面上。

### 巡检异常会自动进报错记录

同机台、同类型、同一天只留一条并累加次数。
否则每轮巡检都会堆一批重复记录，几天就淹没了真正的问题。

## 给维护者：`.bat` 必须保持纯 ASCII

`启动桥接服务.bat` **不能包含任何非 ASCII 字符**，行尾必须是 CRLF。

原因：cmd.exe 按**控制台 OEM 代码页**（中文 Windows 是 GBK/936）解析 .bat 文件。
如果文件是 UTF-8 保存且含中文，这些字节会被当成乱码命令，
解析中断、窗口**瞬间闪退**——而且不给任何错误提示。

```
症状：双击 启动桥接服务.bat → 黑窗口一闪而过
原因：文件是 UTF-8 含中文，cmd 按 GBK 读，字节被曲解
修法：正文全部改英文；中文输出交给 Python（它自己会设 UTF-8 输出）
```

自检命令：

```bash
python -c "d=open('启动桥接服务.bat','rb').read(); print('non-ascii:', sum(1 for b in d if b>127))"
# 必须输出 non-ascii: 0
```

脚本里的 `chcp 65001` 只影响**控制台输出**，**管不了 cmd 对脚本本身的解析** ——
这是最容易误解的一点：加了 `chcp 65001` 并不代表 .bat 里就能写中文。

另外 `cd /d "%~dp0"` 放在 `chcp` **之前**：项目如果放在含中文的路径下，
先切代码页再 `cd` 可能切不过去。

## 常见问题

**端口被占用？** 换一个：`python lava_bridge.py --port 8771`，
同时把页面「接入设置」里的地址改成一样的。

**页面显示「桥接未启动」？** 确认那个黑窗口还开着。关掉窗口服务就停了。

**FTP 连不上但桥接正常？** 「桥接正常」和「FTP 正常」是两回事 ——
前者只说明本机服务可访问，后者才说明现场 FTP 也连通。点「检测连接」看具体哪一项失败。

**手机能访问吗？** 可以，但要显式开启：

```bash
python lava_bridge.py --host 0.0.0.0 --allow-remote --token 你的令牌
```

手机和电脑要在同一局域网，且页面「接入设置」里填同样的令牌。
**生产网络请务必改掉默认值。**
